# Integration bugfix ledger

These are runner defects found during the first native Windows WordPress integration, separate from performance results and new supervisor functionality.

| Defect | Effect | Fix and regression evidence |
| --- | --- | --- |
| Plugin messages mistaken for PHP failures | AIOSEO's companions write ordinary migrations and missing-account messages through `error_log()`. The runner treated any log bytes as a PHP warning and would stop even when setup/output were valid. | Retain every log byte and its digest; check native PHP warning/notice/deprecation/error formats before collection and after each pass. Other plugin messages remain explicit review limitations, including unavailable account features. A regression uses the observed messages and all native diagnostic severities. Logging remains enabled. |
| AJAX bootstrap omitted AIOSEO's setup REST API | The CLI helper marked configuration as AJAX. AIOSEO deliberately omits its wizard API in that context, so internal REST dispatch could not reach it. | Bootstrap configuration as an authenticated REST context with AJAX disabled, leaving installation/activation behavior intact. A fresh-process regression checks all three action contexts before plugin loading. |
| Local environment disabled native indexing | The fixture declared `WP_ENVIRONMENT_TYPE=local`. Yoast 28.8 deliberately refuses to save indexables outside production, so setup repeated its first batch until the safety bound stopped the run. | Use production WordPress behavior for every isolated fixture, report the effective environment over HTTP, and refuse reference qualification when it is non-production or unknown. Network, update, cron, and access guards remain separate. No timing samples from the failed attempt are reused. |
| Incorrect WordPress archive root | Provisioning passed `WordPress` to the extractor, while official archives contain `wordpress/`. The case-sensitive safety check correctly refused it before extraction. | Use the actual lowercase distribution root. An offline provisioning regression now extracts a synthetic archive with that exact structure, renders configuration, and verifies the ownership journal. Scope the prose spelling diagnostic away from this protocol identifier so automatic formatting cannot capitalize it again. Traversal checks remain intact. |
| Cleanup receipt dropped table prefixes | The database helper returned suffixes such as `posts`; its caller requires full table names to verify ownership. Live cleanup could drop owned tables and then refuse the receipt. | Return full names. The subprocess mysqli-double regression now asserts the complete removed name and still checks that unrelated and neighboring-prefix tables survive. |
| Preflight namespace outside the cleanup contract | The first supervisor preflight appended letters to the hexadecimal namespace, which the strict cleanup script rejects. | Derive a separate 12-hex-digit namespace from the parent identity. Keep the strict cleanup format and independent ownership journal. Failed first-attempt evidence is retained. |
| Native diagnostic encoding | nginx's Windows syntax diagnostics can contain non-UTF-8 path bytes, which cannot be serialized directly as JSON. | Keep the original streams and their hashes; use a readable JSON fallback only for diagnostic text. A regression verifies byte-for-byte retention. Behavioral fixture JSON stays strict. |
| Unicode nginx command arguments | Passing absolute non-ASCII paths through nginx's Windows command-line handling failed the syntax check. | Launch from the owned directory with relative prefix/config arguments. Native startup and automatic shutdown were verified in a non-ASCII operation path using inbox PowerShell 5.1. |
| Cleanup error masked the initiating preflight failure | A failure during recovery could replace the original setup exception in CLI output. | Preserve the initiating exception and store cleanup errors separately while still stopping the owned server job. |

Local's Windows CGI recycling failure was reproduced independently of WordPress. It is a host-stack issue; no Local program files were modified. The optional owned supervisor is a separate feature and must pass actual WordPress preflight before plugin timings are collected.
