# Review and regression ledger

This ledger distinguishes confirmed runner fixes from live benchmark validation. The checks below use isolated PHP processes and WordPress/database stubs. They do not install WordPress, connect to MySQL, or certify Local on either operating system.

| Area | Confirmed problem | Change | Regression evidence |
| --- | --- | --- | --- |
| Local target export | A failed JSON encoding or write could still report success. An existing dangling symlink could be followed. | Encode before writing; reject links; create exclusively; check the write and flush. | Fresh export, existing-file preservation, served-directory rejection, and invalid UTF-8 failure. The dangling-symlink subprocess case runs on Unix; Windows does not assume symlink privileges. |
| Fixture setup | An unknown operation or existing result destination was rejected only after WordPress loaded, or could overwrite a receipt. | Validate before bootstrap and create result files exclusively with checked writes. | Rejected actions, URLs, and existing receipts never execute the WordPress bootstrap stub. |
| OptinMonster defaults | Pre-filling its option with only a privacy flag prevented its native default configuration from initializing. | Leave its initial option absent; its pinned native default already declines usage tracking. Retain the later privacy verification. | The installer stub asserts that it does not pre-fill `optin_monster_api`. The behavior was checked against the pinned 2.17.1 source. |
| Database cleanup | Splitting on the first colon confused WordPress's `host:port:/socket` form and IPv6. Failed DROP results were not checked directly. | Parse socket, host, and port separately; preserve mysqlnd's IPv6 convention; require successful inspection and drops. | Stubbed connection cases cover ports, sockets, IPv6, untouched neighboring prefixes, and failed drops. No database connection is made. |
| Cleanup ownership | The prefix pattern accepted a trailing newline because it used `$`. | Require absolute start/end anchors. | A newline-suffixed prefix fails without a success receipt. |
| Yoast setup | Internal REST dispatch returns object data for configuration, while the helper originally accepted only arrays. | Normalize `stdClass` data while rejecting unsuccessful or malformed responses. | Object success, object failure, scalar failure, and bounded incomplete indexing cases. |
| Runtime diagnostics | Runtime validation could throw before the settings responsible for rejection were saved. | Save the initial observation and each later runtime receipt before assessing them. | Reviewed failure paths preserve the observation; the existing runtime tests still cover blocking and reference-only conditions. A live interrupted collection remains untested. |
| Concurrent commands | Two mutating commands could act on the same run at once. | Hold a run lock for the mutation and release it when the command ends. | Synthetic lock contention and release tests. |
| Evidence writes | Partial writes or interrupted replacement could damage saved JSON, reports, or CSV output. | Write complete replacements atomically; check sample writes and flushes; check CSV serialization before replacement. | Atomic replacement, preserved float identity, and evidence replay tests. |
| Archive paths | A ZIP could contain a path used both as a file and as a directory. | Reject collisions in the complete archive inventory before extraction. | An adversarial synthetic ZIP leaves no partial extracted output. |
| Cleanup paths | A journal path or linked ancestor could redirect cleanup away from the approved fixture. | Reconstruct the exact approved directory and prefix, then reject linked ancestry. | Containment and ownership refusal tests; no unrelated resources are removed. |
| Target configuration | Relative runtime paths and truthy strings could change the meaning of approved settings. | Resolve paths before approval and require a Boolean download setting. | Synthetic planning cases cover relative paths and invalid download values. |
| Custom recipes | A modified suggested recipe could retain its reference label or fail before being classified as custom. | Normalize changed reference recipes to custom experiments before validation. | Recipe validation and custom-experiment tests. |
| Private recipe identity | A changed recipe file could diverge from the plan whose approval was recorded. | Compare private recipe evidence with the approved plan before collection or analysis. | Private recipe-drift refusal tests. |
| Public exports | Unknown recipe and isolation fields, credential-bearing URLs, and UNC diagnostic paths could expose private information. | Export consumed recipe fields, restrict isolation receipts, refuse sensitive package URLs, and redact private paths. | Adversarial export cases, manifest verification, and independent report replay. |
| Source identity | Receipt digests were accepted without checking their file maps; generic secret-key redaction could also alter legitimate source filenames. | Verify nonempty source maps against their digest and preserve validated relative filenames. | Mismatched/empty manifests reject; names such as `tokenizer.php` survive unchanged. |
| Runtime qualification | Contradictory Xdebug evidence or an initial blocking condition in a custom run could escape qualification checks. An unavailable OPcache directive could be mistaken for an enabled disk cache. | Reconcile actual extension evidence, reject blocking conditions for every recipe, and distinguish unavailable directives. | Runtime qualification and custom-experiment refusal cases. |
| Telemetry | Missing or malformed metrics could overstate coverage; invalid dates, mixed units, and numeric overflow could distort summaries. | Validate observations, preserve units and unavailable readings, reject invalid timestamps, and calculate finite summaries. | Missing-metric, timestamp, unit, and overflow regressions. |
| Native monitoring | Windows processor-group counters could be labelled whole-host, and Mac observations could inherit the next block's timestamp. | Report unsupported multi-group CPU coverage explicitly and retain the original Mac observation time and thermal state. | Native Windows smoke test and the actual Mac parser exercised with synthetic chunks. Live Mac collection remains pending. |
| Re-export integrity | Re-export could replace a damaged public source manifest with newly generated evidence. CLI alternate analysis also created a lock file inside its source bundle. | Verify an existing source manifest before export and keep public sources immutable. | Intact re-export, corrupted-source refusal, and CLI alternate analysis preserve and verify source and destination manifests. |
| Fixture preflight | Invalid or missing result destinations could reach WordPress before being rejected. | Reject empty, malformed, existing, or parentless paths before bootstrap. | Fresh subprocesses verify that invalid paths neither load WordPress nor emit warnings. |
| Embedded source | Large inline stubs and quoted configuration code escaped normal syntax and style inspection. | Store PHP and JavaScript stubs in separate files, load them with checked reads, and render the configuration from a real template. | Extracted installer/parser tests and executable configuration tests cover quotes, binary data, and template-marker text in credentials. |
| Final cleanup proof | A malformed or unfinished database receipt could be discovered only after recovery files were removed. A replaced regular file could bypass the directory ownership check. | Validate the complete owned-table receipt before removing files; reject replaced paths and linked ownership markers. | Invalid JSON, nonzero remainders, malformed/unowned table lists, replaced paths, and mismatched owners retain recovery data. |
| Linked filesystem ancestors | The link-removal branch could unlink an unrelated entry through a redirected parent; atomic writes and run locks also needed ancestor checks. | Refuse linked parents before mutation, retaining ordinary relative-path support. | Native Windows junction tests preserve unrelated files and links and prevent redirected locks. Equivalent symbolic-link cases run on Unix. |
| Failed extraction | A later destination conflict could leave earlier output; a corrupt entry could retain partial data. Windows-illegal names could fail only after writing began. | Preflight every destination and ancestor; reject nonportable names; remove only the incomplete file created by the failing copy. | Adversarial ZIPs cover late collisions, CRC failures, and illegal characters while preserving existing data. |
| Nested receipt identity | An outer public manifest could hide inconsistent inner receipt digests; malformed output selections could carry metadata outside their fingerprint. | Validate inner source/output identities and require proper lists and relative filenames. | Correctly hashed adversarial receipts reject empty names, associative selections, and inconsistent inner digests. |
| PHP coding standards | Manual checks missed naming, variable-key spacing, file/exception documentation, and alignment diagnostics from the installed PHPCS engine. | Rename internal helpers and variables, correct source formatting/docs, and add a TSF-based PHP 8.2 ruleset with narrowly scoped CLI and API-double exceptions. | Full PHPCS checks and the complete regression suite; a temporary comparison-precedence conversion error was detected by regressions and corrected before acceptance. |

The test harness treats unsuppressed PHP warnings and notices as failures and loads shared test helpers before executing cases. Review-time checks also include PHP lint and the repository's formatting checks; these are separate from behavioral evidence.

Setup API inspection uses pinned cached PHP source. It supplements the stub tests; it does not prove that a complete live plugin activation and setup succeeds. The generated source, package identities, output qualification, and all timing passes still need an approved native integration run.

The instructions keep reference timing separate from profiling, retain unfavorable results, label unavailable sensors, and reject unsupported non-HTML cohorts. No benchmark winner is a correctness requirement.
